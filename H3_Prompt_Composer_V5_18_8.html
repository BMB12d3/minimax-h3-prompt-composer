Media labels and reusable Picture routing

Project image names are not automatically H3 Picture slots. Use P## only when you truly mean a fixed physical ComfyUI Picture input. Environment views are normally reusable library media: name them by environment + view, then route them into the available Picture inputs for each Generation.

Recommended pattern: keep recurring character/object references pinned when that makes your workflow easier, but let environment views reuse the remaining Picture inputs. Example with four pinned Subjects: Jungle Clearing views can use Pictures 5–6, Jungle Road can reuse Picture 5, and Broken Bridge views can reuse Pictures 5–7. Different Environment nodes may intentionally share those same slot numbers because only the selected Environment is active in a Generation.

When giving files to the AI: label each Environment consistently and distinguish its views (WIDE, APPROACH, SHED_SIDE, RAMP_DETAIL, etc.). The order you upload images or a name like “image 10” is only a project-media identifier unless you explicitly say it is physical Picture 10. After import, verify the Picture chips on each Environment node match what you will actually connect in ComfyUI for that Generation.

Import AI Setup JSON

Paste the JSON returned by the LLM or open a .json file. Pasted JSON is checked automatically. The JSON’s operation field decides what happens: replace_project replaces the whole project, while append_generations (returned when you use Copy next-Generation context) merges the new Generation(s) into the current project. Structural/schema problems block import; Prompt Check problems are shown clearly but may still be imported so you can fix them inside the Composer.
